你的直觉**有一半是对的，但也非常危险**。

直接回答你：**“两个变量越大越好 $\rightarrow$ 按 $a+b$ 排序” 这个结论是不成立的。**

在算法竞赛中，决定是加法（$a+b$）、乘法（$a \times b$）还是除法（$a/b$），**不取决于“是不是越大越好”，而取决于这两个变量在题目物理意义中是如何“纠缠”在一起的。**

我教你一个**比“邻项交换法”更直观、更快的判断技巧**，叫**“单位量纲分析法”（物理直觉法）**。

---

### 核心判断技巧：看“单位”

这是物理学思维在算法里的降维打击。你不用推公式，看一眼单位就知道能不能相加。

#### 1. 什么时候是加法 $A+B$ 或减法 $A-B$？
**特征：两个变量的单位是一样的。**

*   **例子（本题 - 堆箱子）：**
    *   重量 $W$ 的单位是 **kg**。
    *   承载力 $D$ 的单位是 **kg**。
    *   **直觉**：$W$ 和 $D$ 单位相同，物理上它们可以相加（$W+D$ 有物理意义，表示“总结构强度”）。
    *   **逻辑**：题目中的限制是线性的（累加重量 $\le$ 承载力）。线性约束通常对应加减法排序。

#### 2. 什么时候是比率 $A/B$？
**特征：两个变量单位不同，且我们追求“性价比”或“效率”。**

*   **例子（排队打水 / 贪心做任务）：**
    *   任务价值 $V$ 的单位是 **元**。
    *   耗费时间 $T$ 的单位是 **秒**。
    *   **直觉**：你能把“元”和“秒”相加吗？$10元 + 5秒$ 是什么鬼？没意义。所以绝对不是 $A+B$。
    *   **逻辑**：我们要么追求“单位时间的价值”（$V/T$），要么追求“单位价值的耗时”（$T/V$）。
    *   **排序**：按 $V/T$ 排序。

#### 3. 什么时候是乘法 $A \times B$？
**特征：变量是无量纲的（倍率），或者涉及由于“累乘”导致的放大效应。**

*   **例子（国王游戏）：**
    *   左手数字 $L$ 和右手数字 $R$ 在题目中表现为“乘积”的形式。
    *   虽然它们可能看起来像某种“能力值”，但在公式里，它们是作为**乘数**出现的。
    *   **直觉**：如果公式里是 $A \times B \times C \dots$，那么排序条件通常也逃不开乘法。
    *   **排序**：按 $L \times R$ 排序。

---

### 为什么你的“越大越好”直觉会失效？

举个反例你就明白了。

**题目：** 有两个任务，每个任务有两个属性：
1.  **重要度 A**（越大越好）
2.  **紧迫度 B**（越大越好）

你想先做哪个？
*   如果按你的直觉 $A+B$ 排序：一个重要度 100、紧迫度 1 的任务（$101$），和一个重要度 50、紧迫度 50 的任务（$100$）。你会先做前者。
*   但如果在题目逻辑里，总得分 = $\sum (重要度 \times 紧迫度)$ 或者 $\sum (重要度 / 紧迫度)$ 呢？
    *   这时候加法排序就完全错了。

---

### 终极判断表（建议截图保存）

下次遇到 $a$ 和 $b$ 两个变量，不要猜，按这个表对号入座：

| 题目特征          | 变量关系          | 物理/数学直觉          | 排序依据 (大概率)       | 经典例题                        |
| :---------------- | :---------------- | :--------------------- | :---------------------- | :------------------------------ |
| **累积限制**      | **线性** (Linear) | 单位相同 (kg vs kg)    | **$a + b$**             | 堆箱子、流水线加工              |
| **效率/性价比**   | **除法** (Ratio)  | 单位不同 (元 vs 秒)    | **$a / b$**             | 护花(POJ3262)、最小加权完成时间 |
| **连续缩放/乘积** | **指数/乘法**     | 倍率因子 (无量纲)      | **$a \times b$**        | 国王游戏、皇后游戏              |
| **简单阈值**      | **独立**          | 一个是门槛，一个是代价 | **只按 $a$ 或只按 $b$** | 简单的区间调度                  |

### 总结

回到你最开始的问题：
> “如果说这两个变量越大越好，那么就是 $a+b$，你觉得我说的对吗？”

**答案是：不对。**
*   在堆箱子这道题里，是因为 $W$ 和 $D$ 都是重量单位，且约束条件是线性的（累加），所以凑巧是 $W+D$。
*   如果换一道题，比如“每个箱子每压一秒钟损失 $C$ 元，箱子高度是 $H$”，求最小损失。虽然 $C$ 和 $H$ 可能都是越大越好（假设），但因为单位不同（元 vs 米），排序依据绝对是 $C/H$ 或 $C \times H$，绝不可能是 $C+H$。

**一句话心法：**
**单位一样试加减，单位不同试乘除。**

### 第一阶段：邻项交换法 (Exchange Argument)
**目标**：不再瞎猜是按 $A+B$ 排还是 $A \times B$ 排，学会用不等式推导排序规则。

#### 1. [Luogu P1080] 国王游戏 (NOIP 2012 提高组)
*   **难度**：⭐⭐⭐
*   **核心点**：这是**乘法排序**的鼻祖。题目要求最小化最大奖金。
*   **训练目标**：请务必在草稿纸上推导出为什么要按 $L_i \times R_i$ 排序。如果不推导直接写代码，这道题就没有意义。
*   **提示**：比较 $(i, j)$ 和 $(j, i)$ 的最大值表达式。

#### 2. [Luogu P2123] 皇后游戏
*   **难度**：⭐⭐⭐⭐
*   **核心点**：国王游戏的升级版，公式更复杂。
*   **训练目标**：推导排序公式。你会发现这里不再是简单的乘积，而是涉及 $\min$ 和加法。结论是按 $\min(a_i, b_j) < \min(a_j, b_i)$ 这种形式排序（实际上有更简单的等价形式）。

#### 3. [POJ 3262] Protecting the Flowers (护花)
*   **难度**：⭐⭐
*   **核心点**：典型的**比率排序**（性价比）。
*   **题目大意**：牛吃花，每分钟损失 $D_i$，赶走它需要 $T_i$ 时间。
*   **训练目标**：推导出按 $D_i / T_i$（单位时间的损失）排序。

---

### 第二阶段：基础反悔贪心 (Regret Greedy)
**目标**：学会“先选上，后面发现不对再把最差的踢掉”的思维，熟练使用 `priority_queue`。

#### 4. [Codeforces 865D] Buy Low Sell High
*   **难度**：⭐⭐⭐
*   **核心点**：反悔贪心的入门必做题。
*   **题目大意**：已知未来 $N$ 天的股价，每天可以买、卖或不操作，求最大利润。
*   **思路**：把当天的价格放入小根堆。如果当前价格高于堆顶，就“假装”卖出（累加利润），并把当前价格再次压入堆（为了以后能“反悔”这次卖出，相当于没卖，留到更高价卖）。

#### 5. [Codeforces 1526 C2] Potions (Hard Version)
*   **难度**：⭐⭐⭐
*   **核心点**：**这道题的逻辑和你的“堆箱子”完全一样，只是背景换了。**
*   **题目大意**：从左到右喝药水，药水有正有负，生命值不能小于 0。问最多能喝多少瓶？
*   **思路**：能喝就喝（生命值加）；喝了会死怎么办？看看堆里有没有喝过的“最毒”的药水（负得最多的），如果比当前这瓶还毒，就“反悔”——吐出那瓶最毒的，喝当前这瓶。

---

### 第三阶段：终极结合 (排序 + 反悔)
**目标**：同时解决“顺序”和“子集选择”两个问题。也就是你今天卡住的类型。

#### 6. [Luogu P4053] [JSOI2007] 建筑抢修
*   **难度**：⭐⭐⭐⭐
*   **核心点**：**这是“堆箱子”问题的孪生兄弟。**
*   **题目大意**：修理建筑，修第 $i$ 个需要 $T_i$ 时间，必须在 $D_i$ 时刻前修完。问最多能修几个？
*   **逻辑**：
    1.  **排序**：按截止时间 $D_i$ 从小到大排（邻项交换法推导结论，先修截止早的）。
    2.  **反悔**：遍历，能修就修；修不完？看之前修过的哪个耗时 $T$ 最长，如果比现在的长，就“反悔”不修那个长的，改修现在的。
*   **代码结构**：和你的堆箱子代码几乎一模一样。

#### 7. [Luogu P2949] [USACO09OPEN] Work Scheduling G
*   **难度**：⭐⭐⭐⭐
*   **核心点**：带截止日期和利润的工作调度。
*   **思路**：按截止日期排序，用小根堆维护已选工作的**利润**。如果时间不够了，看能不能踢掉一个利润低的，换个利润高的。

        ```cpp
        priority_queue<int> pq; // 大根堆还是小根堆看题目（是要踢掉最大的还是最小的）
        for (item : items) {
            if (can_take(item)) {
                take(item);
                pq.push(item.value);
            } else if (!pq.empty() && item.better_than(pq.top())) {
                undo(pq.top());
                pq.pop();
                take(item);
                pq.push(item.value);
            }
        }
        ```
